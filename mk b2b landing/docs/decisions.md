# Decisions and deviations from SPEC.md

| Date | Topic | Decision | Why |
|---|---|---|---|
| 2026-11-05 | Package manager | npm instead of pnpm (`npm run check` = `pnpm check`) | §14.1 allows either; pnpm is not installed here |
| 2026-11-05 | Routing | One catch-all route `src/pages/[...path].astro` built from `locales.ts` + `routes.ts` rather than Astro's `i18n` config | Translated path segments, and a new locale needs no new page file |
| 2026-11-05 | Page copy format | JSON (`content/landing`, `faq`, `legal`) instead of MDX | Pages are structured sections, and parity checks are simpler |
| 2026-11-05 | Hero secondary CTA | "Sortiment ansehen" until a catalogue PDF exists | D5 hides the catalogue CTA; set `site.catalogPdf` to restore it |
| 2026-11-05 | Card link | Every card links to the RFQ with the product preselected; no "Details" link | Product pages are Phase 2, and §7.3 keeps them unpublished until reviewed. Category-page links are also Phase 2 |
| 2026-11-05 | Product model | Added `types` and chair measures `depthMm`, `seatHeightMm` | Needed for the §6 filters and chair dimensions |
| 2026-11-05 | Photos | Main-site 1000 px product photos as stand-ins, served up to 1000 px wide; widths 320/480/800 on cards | Originals not yet supplied (§3.2). Replace in `assets/originals/` |
| 2026-11-05 | Plurals | `Intl.PluralRules` selecting a `countOne`/`countOther` string | §5A.6 asks for ICU syntax, but a full ICU runtime is not worth the JS for one string. Revisit if plurals multiply |
| 2026-11-05 | `inLanguage` | Only on CreativeWork nodes (WebSite, WebPage, FAQPage) | §10.3 says every node, but schema.org does not define it for Organization, Service or ItemList |
| 2026-11-05 | FAQ JSON-LD | Excludes answers that still contain TODO(client) | Markup must not state unfinished facts |
| 2026-11-05 | `availableLanguage` | Left out of Organization | Appendix B: only languages sales can really answer in; unknown |
| 2026-11-05 | Email provider | Brevo (EU) API in `rfq-handler.ts`, one small function to swap | §12 asks for an EU provider and names none. Not yet tested against the real API |
| 2026-11-05 | Rate limit | In-memory per isolate | Best effort; add a Cloudflare rate-limiting rule on `/api/rfq` at launch |
| 2026-11-05 | Time trap | Runs only when JS set the `ts` field | A static page cannot stamp a time without JS; honeypot and rate limit still apply |
| 2026-11-05 | Trust-bar wording | "massiv, geölt oder lackiert" | Short form of C4 |
| 2026-11-05 | Phone product cards | One column kept, but each card is a row (photo 38 %, text beside it) at 480 px and below | §8.4 asks for one column; full-width cards made the range 21,300 px tall. Trade-off: smaller photos on phones until Phase 2 product pages exist |
| 2026-11-05 | Card action | With JS the card link becomes a toggle "Zur Anfrage hinzufügen" that ticks the model in the form and stays in the range. Count shows on the header CTA and sticky bar. Without JS it stays a link to the form | Buyers usually ask about several models. §6's "Details" link stays Phase 2. Selection lives only in the form's checkboxes: no storage |
| 2026-11-05 | Filters on small screens | Collapsed behind a "Filter" button below 1024 px; expanded on desktop | The chips took about 290 px per block on phones. Filters already need JS, so nothing is lost without it |
| 2026-11-05 | Range jump links | Sticky Tische/Stühle links with counts inside the range section | Chairs otherwise start far down the page. Category-page links are still Phase 2 |
| 2026-11-05 | Form layout | USt-IdNr., Maßanfertigung and drawings link moved into a collapsed "Weitere Angaben (optional)"; Segment sits beside Land und PLZ | All §12 fields remain and post as before; the first view of the form is shorter. Errors inside the fold open it |
| 2026-11-05 | Visual redesign (client request) | Replaces §8's look. From the main site only the logo and colour tokens remain. New: Bricolage Grotesque + Manrope (self-hosted) instead of uppercase Montserrat; rounded corners and pill buttons instead of square; floating header and phone bar; dark hero, bento tiles, inset dark panels; sliding photo band | Client asked on 2026-11-05 for a modern design using only the original colours and logo. Overrides §8.1 radius and font, §8.2 and §8.3. Binding rules kept: WCAG 2.2 AA, budgets, CSP, no third-party requests, no JS for primary content |
| 2026-11-05 | Motion | Scroll-linked reveals, parallax, progress bar and sliding band, CSS only (`animation-timeline`). Off for reduced motion; browsers without support show everything in place | §8.6 asks for subtle fades and hover only. Goes further at the client's request; still no scroll-jacking and no autoplay video |
| 2026-11-05 | Cyrillic | Bricolage Grotesque has no Cyrillic subset; Manrope has | No live or planned locale in the build needs it today. A Cyrillic locale would need a display font decision (§8.2) |
| 2026-11-05 | Preview server | `scripts/preview-server.ts` now gzips text responses | Real hosts compress, so Lighthouse here was overstating download time (LCP 2.6 s uncompressed, 2.0 s compressed) |
| 2026-11-05 | Axe audit setup | Axe runs with reduced motion and the sticky bars static; focus-under-sticky-bars has its own test | Otherwise results depend on axe's scroll position and on fades caught mid-way. The resting state is what is audited |
| 2026-11-06 | Form captcha (client request) | Self-hosted proof-of-work (`src/lib/captcha.ts`, `GET /api/captcha`, secret `RFQ_CAPTCHA_SECRET`), on top of honeypot, time trap and rate limit. Without JS a `<noscript>` sum question takes its place. Required on every path including JSON | D9 said Turnstile only if spam appears; the client now wants a captcha. reCAPTCHA, hCaptcha and Turnstile load third-party scripts, which the no-third-party rule forbids. Known limit: it raises a bot's cost, it does not stop a determined one, and the fixed no-JS answer is trivial for a targeted bot |
| 2026-11-06 | Agents and the captcha | Agents use the same check: solve `/api/captcha` or send `captchaAnswer` | §11 asks for the same spam checks on agent requests. Phase 3 `openapi.json` and `llms.txt` must document this or the RFQ test (§11.3) fails |
| 2026-11-06 | Section order | Segments moved above the range | §6 lists range first. Buyers place themselves first, and the catalogue no longer buries the segment links |
| 2026-11-06 | Range display | With JS, Tables/Chairs switch in place and each list starts at 8 cards with a "show all" button; filters show every match; `#product-x` opens the right block. Without JS both full lists show | All 36 stay in the HTML and JSON-LD, so crawlers and raw fetches lose nothing. Trade-off against §6 "no content depends on JS": a browser-based agent sees 8 until it presses the button |
| 2026-11-06 | Form order | Three numbered groups: need, contact details, confirm and send. Single page, no wizard, so no fields hide without JS | §12 lists contact fields first. Starting with the request is easier than starting with personal data. The first error focused now follows reading order |
| 2026-11-06 | Language switcher | Dropdown with two-letter codes (DE, EN), built on `<details>`; always in the header pill, also on phones, and in the footer. Screen readers hear the full language name | Client request; §5A.6 describes a switcher with language names. Codes come from the locale key, so a new locale needs no code change |
